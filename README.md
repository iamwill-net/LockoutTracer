# Lockout Tracer

Lightweight single-file GUI (`LockoutTracer.exe`, .NET Framework 4.5+, which every Server 2012+ has built in).
Copy it to a domain controller, run it, type a user name, and it shows when and why the account locked out.

**Download:** get `LockoutTracer.exe` from the [Releases](../../releases) page, or build it from source (see [Build](#build)).

## What it does
1. **AD (via the PDC emulator):** lock state (`msDS-User-Account-Control-Computed`), lockoutTime, pwdLastSet,
   effective lockout policy (Default Domain Policy or fine-grained PSO), enabled, expiry.
2. **Every DC (LDAP):** `badPwdCount`, `badPasswordTime`, `lastLogon`. These are not replicated, so they're read per DC.
3. **Every DC (Security log, remote):** events for the user in the look-back window:
   - 4740 lockout (*Caller Computer Name* = the source), 4767 unlock (who unlocked it)
   - 4771 / 4768 Kerberos failures (client IP, 0x18 bad password, 0x12 already locked)
   - 4776 NTLM failures (workstation name)
   - 4625 failed logons at the DC (IP, workstation, logon type, process)
4. **Likely sources tab:** groups failures by IP or machine (with reverse DNS), counts lockouts and failures,
   and gives a plain-English hint (service with an old password, scheduled task, IIS/ActiveSync, Kerberos with a cached password,
   NTLM relayed by Exchange/NPS, and so on). Double-click a source to filter the Events tab to it.
5. **Unlock account** (on the PDC, with confirmation) and **Export** (events, sources, DCs as CSV, plus the summary as TXT).

It can also be started from the command line: `LockoutTracer.exe jsmith` pre-fills the user and starts the trace.

## Requirements and limitations
- Run it as a Domain Admin, or an account in *Event Log Readers* on each DC. The EXE asks for elevation because the local Security log needs it.
- To read other DCs' logs, the **Remote Event Log Management** firewall rules must be enabled on them. Unreachable DCs are
  listed under *Coverage warnings*; the rest of the result still shows.
- Results are limited by each DC's Security log retention. The DC tab shows *Log starts*, and the tool warns when that is newer than the look-back window.
- The Security log needs *Audit Account Lockout*, *Kerberos Authentication Service* and *Credential Validation* (failure)
  auditing enabled. These are on by default for DCs in the Default Domain Controllers Policy on modern Windows.
- Event log XPath queries are case-sensitive, so the tool searches the entered name, sAMAccountName and UPN in lower, UPPER and Title case.
  Events where a client sent the name in mixed case (for example `jSmItH`) will not be matched.

## Build
```powershell
.\build.ps1          # uses %WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe; no SDK/VS needed
```
Sources: `src/Engine.cs` (AD, event-log queries, parsing, source grouping) and `src/MainForm.cs` (WinForms UI).
`src/app.manifest` sets requireAdministrator and DPI awareness. `src/app.ico` is generated by `icon/MakeIcon.cs` (padlock + magnifier, 16-256 px).
